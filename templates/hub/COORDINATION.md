# 에이전트 협업 약속

- 상태: 틀. 허브가 프로젝트에 맞게 채운다
- 적용: 이 프로젝트 저장소에서 일하는 Claude 세션
- 상위 규칙: 접속, 비밀값, 배포는 각 저장소나 상위 폴더의 `CLAUDE.md` 가 우선한다. 이 문서는 에이전트 사이의 약속만 다룬다
- 고치는 쪽: 허브. 워커는 보고로 요청한다

## 1. 용어

| 말 | 뜻 |
|---|---|
| 허브 | 이 폴더에서 뜨는 세션. 배정하고 보고를 받아 기록한다. 직접 구현하지 않는다 |
| 레인 | 한 에이전트가 맡는 작업 영역. 폴더 기준으로 정한다. 세션 이름 기준으로 정하지 않는다 |
| 작업 공간 | 한 에이전트가 쓰는 작업 트리 하나(클론 또는 `.claude/worktrees/` 아래) |
| 상주 세션 | 레인을 계속 맡는 세션. `agents.json` 의 `resident` |
| 일회성 세션 | 작업 하나를 맡고 닫는 세션. `agents.json` 의 `task`, 이름은 `task-<주제>` |

## 2. 레인과 소유권

소유 레인만 그 경로에 커밋한다. 다른 레인이 고쳐야 하면 허브를 거쳐 요청한다.

| 레인 | 소유 경로 | 비고 |
|---|---|---|
| HUB | 허브 폴더 | 이 문서, `STATUS.md`, `agents.json`, `decisions.json`, `dev-occupancy.json` |
| `<레인>` | `<저장소 또는 폴더>` | `<상주 세션 이름, 금지 규칙>` |

- 허브 폴더는 허브만 쓴다. 다른 세션의 Edit/Write 는 agent-hub 플러그인 훅이 막으니, 바꿀 내용은 허브에 보고한다.
- 한 작업 트리에 세션이 여럿이어도 바로 나누지 않는다. 같은 파일을 같이 고치게 될 때 나눈다.
- 허브가 `claude --bg` 로 띄운 세션은 스스로 `<저장소>/.claude/worktrees/` 아래로 옮겨 가니 그대로 둔다.
- 각 저장소 `CLAUDE.md` 의 금지 규칙은 소유 레인이 지키고, 허브는 배정할 때 다시 알려 준다.

## 3. 인터페이스

두 레인 이상이 기대는 약속. 근거 파일이 원본이고, 이 표는 목록이다.

| ID | 인터페이스 | 제공 | 쓰는 쪽 | 근거 |
|---|---|---|---|---|
| IF-01 | `<API, 스키마, 파일 형식, 명령 이름>` | `<레인>` | `<레인>` | `<근거 파일>` |

### 바꾸는 절차

1. 바꾸려는 레인이 보고의 "인터페이스 영향" 칸에 적는다. 쓰는 쪽이 바꿔 달라고 할 때도 같다.
2. 허브가 변경 로그에 "제안" 으로 한 줄 넣고, 쓰는 쪽 레인에 영향을 확인한다.
3. 하위 호환이면 제공 레인이 반영한다. 하위 호환이 아니면(id 변경, 컬럼 삭제, 명령 이름 변경) 사용자 결정을 받는다.
4. 반영 뒤 허브가 그 줄 상태를 "반영" 으로 바꾸고 커밋이나 MR 을 붙인다.

## 4. 공유 자원

한 레인이 건드리면 다른 레인 작업까지 같이 움직이는 것. 실행 전에 허브가 `STATUS.md` 로 다른 레인 상황을 확인하고, 사용자 확인을 받는다.

| 자원 | 같이 움직이는 것 | 실행 전 확인 | 담당 |
|---|---|---|---|
| `<운영 반영, 공유 브랜치 병합, 공유 dev 환경>` | `<함께 바뀌는 것>` | `<다른 레인이 시험 중인지>` | `<레인>`. 허브 요청과 사용자 확인 뒤 |

- 공유 dev 환경을 쓰는 실행과 재기동은 허브가 `dev-occupancy.json` 에 적는다. 재기동을 일으키는 병합은 run 항목이 없을 때 한다.

## 5. 배정과 보고

통로는 Claude 세션 사이의 `SendMessage` 다. 세션 이름이 주소이고, 어느 이름이 어느 레인인지는 `STATUS.md` 세션 표와 `agents.json` 이 정한다.

- 사용자 설정 `crossSessionInbound: accept` 가 있으면 메시지가 권한 모드와 관계없이 바로 전달된다.
- 지금 떠 있는 세션을 팀에 넣을 때는 그 세션에서 `/rename <레인>` 을 하고 "<허브 폴더>/COORDINATION.md 를 읽고 그 규칙대로 움직여" 라고 지시한다. 허브가 `STATUS.md` 와 `agents.json` 에 등록한다.
- 허브는 일을 맡길 때 작업 세션을 새로 열 수 있다. 보고를 받아 허브가 만족하면 닫는다. 작업 세션도 이 문서의 소유권과 보고 형식을 따른다.
- 워커는 마일스톤마다, 인터페이스를 바꿨을 때, 막혔을 때 허브에 보고한다. 다른 세션의 요청이 내 범위와 부딪히면 하지 않고 허브에 알린다.

배정(허브가 보냄):

```
[배정] T-YYYYMMDD-NN
레인 / 작업 공간(경로, 브랜치):
할 일:
범위 밖(건드리지 않을 것):
걸리는 인터페이스, 공유 자원: IF-xx / 없음
완료 조건(무엇을 실행해 무엇이 나오면 끝인지):
```

보고(워커가 보냄):

```
[보고] T-YYYYMMDD-NN
상태: 끝 / 일부 / 막힘
바뀐 것: 커밋, MR, 파일
검증: 실행한 명령과 결과, 어느 환경인지
인터페이스 영향: 없음 / IF-xx 무엇이 어떻게
결정 필요:
```

- 메시지 머리의 `[배정]`, `[보고]`, `[알림]` 은 대시보드 흐름 탭이 종류를 나누는 데 쓴다.
- 보고와 세션 사이 메시지에 데이터 값을 넣지 않는다. 행, 집계값, 고객 내부 명칭과 수치, 키를 쓰지 않고 파일 경로나 id 로 가리킨다. 강제 장치가 없는 규칙이라 허브가 보고를 받을 때 확인한다.
- 인터페이스를 바꾸는 보고는 요약만 보내지 않고, 이 문서의 해당 IF 줄을 어떻게 바꿀지 diff 와 커밋이나 MR 링크를 함께 보낸다.
- 메시지가 안 가는 세션(목록에 없음)은 대개 오래 붙은 사람 없이 지나 프로세스가 멈춘 것이다. 새 세션을 띄우지 말고 `claude respawn <id>` 로 이어 띄운 뒤 `ListAgents` 에 다시 나타나는 것을 보고 다시 보낸다.
- 세션은 띄우기 전에 `agents.json` 에 먼저 등록한다.
- 큰 작업이 끝나면 상시 세션도 새로 띄워 맥락을 리프레시한다. 새 세션에는 STATUS 해당 줄과 남은 일을 인수 프롬프트로 주고 옛 세션은 stop 한다.
- 검증 없이 "끝" 으로 보고하지 않는다. 로컬, 개발 환경, 운영 확인 결과는 섞지 않고 따로 적는다.
- 허브는 보고를 받으면 `STATUS.md` 를 고치고, 인터페이스가 바뀌었으면 7절에 한 줄 넣는다.
